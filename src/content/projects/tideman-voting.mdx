Simulate two elections in which Tideman and plurality pick different winners both times, and my voting tool reports that they agreed 100% of the time.

The tool started as the Tideman problem in Harvard’s CS50. Afterwards I kept going. It now sets ranked pairs beside plurality, the Borda count and the Condorcet winner, simulates random elections, and saves and loads them. `tideman.c` has grown to 1,323 lines. The comparisons are the whole point of it, so a wrong comparison is the bug that matters most.

## How ranked pairs works

Every voter ranks every candidate. For each pair of candidates, the method asks which one more voters preferred, then locks in those head-to-head wins from the biggest margin down, skipping any that would close a loop.

<figure class="os-figure">

```text
 head-to-head wins, biggest margin first

 A beats B by 7   lock it    A --> B
 B beats C by 5   lock it    A --> B --> C
 C beats A by 3   skip it:   C --> A would close a loop

 nobody points at A, so A wins
```

<figcaption>An invented three-candidate example: the two biggest wins are locked in, the third would make a circle, so it is skipped and the candidate nobody beats wins.</figcaption>
</figure>

When one candidate beats everyone head to head, ranked pairs always picks them. That part of the program is right.

## Where the shortcut broke

Plurality counts first choices. My program keeps only the table of head-to-head counts, not the ballots, so it estimates first-place votes by adding up a candidate’s head-to-head support and dividing by the number of opponents. That is the Borda score scaled down.

In the program’s own 9-voter demo, the true first-choice counts are 4, 3 and 2. The estimate ties the top two at 5. So the plurality and Borda columns nearly always agree, and comparing them says little.

The simulation’s agreement figure has the same kind of problem. It counts how often each method picked each candidate across all runs, then matches those totals. If Tideman picks A and then B while plurality picks B and then A, both totals are one win each, and the figure says 100%.

## What I would change

Both fixes are small. Record each ballot’s first choice as the votes come in, and compare winners election by election. Both matter more than any feature the tool gained, and the menu still cannot run a new election, which I never finished.
