At 11:13 UTC on 8 October I committed a change that made my eval worse. On its tuning half the score fell from 61.2% to 49.1%. On its test half it fell from 64.8% to 57.9%.

The commit message called it an honest drop. Of the 74 hits on the tuning half, 21 had found nothing but the session's own brief, the text the session had been handed at the start.

It was not the first leak I closed that morning, or the last. Most of them had one thing in common: they let a past session see something that did not exist yet.

## What the eval measures

[saahil-brain](/projects/saahil-brain) is the memory my coding agents share. On every prompt it hands the agent at most three pointers, each one line, or nothing. The question that matters is whether those pointers lead to the file the session actually needed.

The navigation eval answers it from history. Take a past session from 20 September on, replay its first prompt, and look at the files it went on to use. A hit is a target in the top three pointers, or reachable within three tool calls. Sessions are split by a hash into a tuning half of 110 and a test half of 107. The marks I set are 70% for the top three and 80% within three calls.

## The obvious eval, and its leaks

The first version ranked each old prompt against the brain as it stood that day, and counted every file the session used as a target. It looked fair. It had five ways to flatter itself, and three of them ran time backwards.

- **Its own writes.** A file the session created counted as something the brain should have pointed to.
- **Today's brain.** Ranking ran against everything filed since the session, not the brain the session had.
- **The brief.** When a session started from a pasted brief, the brief counted as a target, and the prompt already held it.
- **Bulk folders.** A folder of project results counted as a file, though no session reads a folder as one.
- **A card from the future.** Short summaries of each project, written days later and staged at a hidden path, slipped past the guard and pointed back to older sessions.

## Replaying the past

The fix is to rebuild the brain as it was when the session began. A guard hides every note and file that shows no sign of existing before that moment. It applies everywhere the ranking looks: the text search, the names in the prompt, the folder anchors, the one hop through links, and the plain keyword search I compare against.

Dating a file turned out to be the hard part. Birth time alone made old files look new: the tool my agents edit with writes a new file on every edit, and a file synced from my other machine is born when it lands. So a file now counts as older than a moment if it was born, last changed, or read by a session that had already ended before it. The memory index and the start-of-session digest are rebuilt as of the same moment.

The splits got the same care. I tune on one half and judge on the other once. Not every fix lowered a score. Counting what the memory index already hands a session before its first call took the test half within three calls from 77.6% to 80.4%. Every new hit was a feedback memory linked from that index.

## What this costs

Replaying the past is a guess about the past. When a file is missing from its path, it is dated by when the index last saw it changed. Excluding the brief also throws away credit for pointers that may well have helped.

The eval I trust most is also the smallest. It takes prompts I typed myself, six words or more, since 1 September, and a model picks the files that answered each one from what the next ten tool calls read. The target is that model's call, not mine.

On one machine the set held 26 prompts. Splitting it by session put 25 in the tuning half, because two long sessions held 20 of them. Splitting by the answer file gives 13 and 13.

Twenty minutes after the brief fix, with pointer changes and one more leak closed, the navigation eval read 72.0% on its test half, over the mark. The eval built from my own prompts reads 15.9% for the top three and 50.7% within three calls.

The two are not measuring the same targets. The navigation eval counts every file a session used, and the human one counts only what a judge picked as the answer. So the gap does not prove the navigation eval still leaks. It does say which number describes real use, and the repository's own lesson says it plainly: the early numbers looked better than real use felt.

## What's next

A daily agent now works on the smallest number first. It tunes a change on one half, measures it once on the other, and keeps it only if, among other bars, the human eval's test half does not drop and the navigation eval stays above its marks. The rule it follows is the one I needed that morning: never edit an eval set, a target or a mark to pass. The code and its lessons are in the [saahil-brain repository](/os#code/saahilsanganeriya/saahil-brain).
